# Changelog

## 0.1.0

- Phase 1: CLI setup, RBAC identity, YAML loader/validate/simulate, GraphEngine with HITL, SQLite sessions/steps/audit, MemoryService (sqlite-memory + FTS fallback)
- Phase 2: ProviderRouter with Mock, Anthropic, OpenAI-compatible/Ollama relay_chain failover; CLI transports (`cursor`, `claude_cli`, `codex`); Cursor Cloud Agents (`cursor_cloud`); workflow provider config merge; `providers:ping`
- Phase 3: SkillRegistry version pins + tool defs; MCP multi-server Manager; GraphEngine ToolLoop with native tool_calls (Anthropic/OpenAI) and TOOL: fallback; `skills:show`, `mcp:list`/`mcp:ping`; engineer `manage_mcp`
- Phase 4: Framework-agnostic `Riggs::Web::App` (Rack) + `riggs serve`; ConfigStore / PM config UI; JSON API; thin Rails Engine mount of the same app
- Phase 6: Durable conversation turns (`riggs_messages`) and gate pause/resume — a `:paused` gate saves resume state, `GraphEngine.resume` / `riggs workflow:resume` / web approve continue the run from the gated step; live run observability via `GET /api/sessions/:id/events` (poll) and `/stream` (SSE) plus a live event log in the session view
- Phase 5: Keyword/manual triggers CLI + `/api/triggers`; interactive `workflow:new` composer (`--non-interactive` for CI); docs and release hygiene
- Phase 7: Token accounting (`Riggs::Usage` vendor-usage normalization, `Riggs::ModelInfo` pricing + context-window table) and token-based compaction — every provider call is metered and priced where the vendor reports it and recorded to `riggs_provider_calls`; `riggs workflow:inspect`, `GET /api/sessions/:id/usage`, and the web session view report tokens in/out and cost per step and per session with explicit coverage on both counters, never rendering an unmeasured or unpriced call as zero; a transcript that exceeds its ceiling compacts (summarize through the relay chain, or truncate if summarization fails) instead of erroring, at both the cross-step and intra-step tool-loop sites; a chain with no metered provider on it has no anchor, so it compacts on character estimates rather than measured tokens and logs one `compaction_unanchored` audit event per session to say the reserve is absorbing a larger error than usual. `reserve_tokens` and `keep_recent_tokens` are scaled to the budget in force (at most a quarter of it, and at most half the resulting ceiling) so the three knobs cannot contradict each other — the shipped 16,384 / 20,000 defaults are lowered against the smaller budgets rather than producing a ceiling of 0 or a compaction that can never reach the ceiling. **Behavior change:** the `anthropic` provider's `DEFAULT_MODEL` is now `claude-sonnet-5`. It was `claude-sonnet-4-20250514`, which Anthropic retired on 2026-06-15 — any call that did not override `model:` was failing. Set `model:` in the provider config to pin a different one. **Behavior change:** `context_window` now means a token budget, not a step count — `short` / `medium` (default) / `full` map to 8,000 / 32,000 / 128,000 tokens. A workflow that declares `context_window: medium` gets different runtime behavior after upgrading — usually *more* history retained than the old 6-step window, not less.
- Phase 7 hardening (adversarial review): seven accounting and compaction defects, none of which the 234-test suite could see because every test picked its own inputs while these only appear on the path production takes. **Cross-step history is now compacted, not dropped** — `build_messages` skipped any step output over the ceiling with no summary, no audit event, and no error, and because the walk ran newest-to-oldest it was the newest output (the handoff into the step being built) that was most likely to vanish. **Dated model IDs now price** — providers report what the API served (`gpt-4o-mini-2024-07-18`), which exact-match lookup missed, so effectively every real OpenAI call was recorded unpriced; lookup now falls back to the longest table key the ID is a dated variant of, for `.agent_hubrc` overrides too. **A measured category with no rate now yields `nil`, not `0.0`** — a model priced for output but not input reported a confident zero for billable input tokens, breaking the nil-not-zero invariant from inside; zero tokens in an unpriced category still price normally, so OpenAI's absent cache-write rate does not unprice every call. **Failed provider attempts now reach the ledger**, recorded unmeasured, so session coverage stops reporting a complete count over a denominator that had already dropped the failure. **Summarization now counts against `max_llm_calls` and inherits the caller's remaining timeout** — it did neither, so `max_llm_calls: 1` bought two provider calls and reported one, and a compaction starting a second before the deadline could run a further 60s past it. **Impossible cache readings no longer produce negative tokens** — `cached_tokens > prompt_tokens` yielded a negative input count that storage summed and pricing turned into a credit; it now reports `nil`, the same as a field the vendor never sent. **Behavior change:** the `mock` provider no longer reports usage. It counted string *lengths* and shipped them as measured token counts, so every offline run displayed roughly 4x-inflated numbers wearing a token label; it now reports unmeasured, like the CLI providers. Tests that need a metered provider should stub one rather than rely on `mock`.
- Phase 8: `SkillRegistry` reads `SKILL.md` (YAML frontmatter plus a markdown body) as well as `SKILL.yml`, so an off-the-shelf skill file from the cross-harness convention drops into `config/riggs/skills/<name>/` and drives a workflow step unmodified. Both containers share one key space (`name`, `version`, `description`, `system_prompt`, `tools`, `mcp_servers`), the markdown body becomes the system prompt, and `SKILL.yml` wins if a directory holds both — no skill that exists today changes behavior. Skill descriptions now appear in `riggs skills:show`, `riggs skills:list`, and the web Skills table. **Behavior change:** a skill file that fails to parse is now skipped with a warning instead of raising. Previously one malformed `SKILL.yml` raised out of `SkillRegistry#list` and took down every command that touched the registry, including runs that wanted a different skill. Riggs still reads only `config/riggs/skills/`; `.agents/skills/` is deliberately not a discovery root, because a repo-local one would let a cloned repository supply a system prompt.
